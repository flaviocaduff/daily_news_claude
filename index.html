  • Normal login and access controls only check whether someone may use a resource. They cannot judge whether an agent's action is appropriate.
  • The risks include prompt injection (hidden instructions that trick an AI), tool and memory poisoning, goal hijacking, behavioral drift, and AI-made-up facts that lead to wrong actions.
  • The framework has three layers: before deployment, during runtime, and after deployment.
  • Before launch, every agent is registered in Uber's AI Registry. A tool called Argus scans agent code, prompts and settings for weaknesses. The same checks apply to MCP servers (a standard for connecting AI to outside tools).
  • At runtime, AI Guards check each proposed action against the agent's policy before it can proceed.
  • After launch, Uber records agent actions. It can replay them to test whether updated rules work.
  • Uber reports challenges: avoiding both false alarms and missed threats, keeping delays low, and reducing friction for developers. Its strongest control was explicit limits for each agent.
  • A UN IT officer, commenting on LinkedIn, warned that per-agent rules cost effort that grows with each workflow. He also asked how this works for vendor agents where companies cannot add their own checks.

Why it matters: Companies that run AI agents need controls beyond passwords and permissions. Otherwise an agent can take harmful actions that look authorized.

Ubuntu Pro users get early access to AI-written security fixes

Canonical, the company behind Ubuntu Linux, gives Ubuntu Pro users early access to AI-written security fixes. The fixes go into a new opt-in package archive called Edge.

  • Ubuntu Pro is Canonical's security-focused subscription service. Edge is off by default, so users must enable it manually.
  • Canonical built Surge, a multi-agent system (several AI agents working together). Surge adapts fixes for known flaws to older software versions, a process called backporting.
  • Surge only covers userspace packages, which are applications and libraries. It does not patch the core kernel, the heart of the operating system.
  • Kernel fixes get faster security updates too. Some users say these are still not fast enough.
  • Edge fixes are not qualified yet, meaning they have not had full testing. Canonical says they will not reach stable releases automatically.
  • Canonical says human review and testing still apply to all updates. Its security team has shipped twice as many fixes as last year.
  • Canonical cites a rise in AI-assisted vulnerability reports and attacks by AI agents as the reason for the faster work.
  • Edge works on Ubuntu 18.04, 20.04, 22.04, 24.04 and 26.04 LTS (long-term support releases). Personal users can use Ubuntu Pro free on up to 5 devices.

Why it matters: Users who accept less testing can get security fixes sooner. Everyone else keeps the usual human-tested updates.

Anthropic adds linked billing for Claude Platform in beta

Anthropic launched linked billing in beta on its Claude Platform. Third-party apps can bill Claude API usage to a customer's account without handling the customer's API key.

  • The Claude API lets software send requests to Claude, Anthropic's AI model. An API key works like a password for those requests.
  • Today, customers often share API keys with apps, so the apps must store and protect them.
  • With linked billing, a customer links their Claude Platform organization to the app. No key changes hands, and usage is billed to the customer's organization.
  • Customers approve each app, set a monthly spend limit per app, and can unlink at any time. An Owner, Admin or Billing role user approves the link.
  • Apps can see each linked customer's request count, token usage (the text units the AI processes), and models used.
  • Apps can decide, per request, whether they or the customer pays. This lets apps cover some features themselves.
  • Requests run in the app's organization. The customer's IP allowlists, encryption keys and data-retention settings therefore do not apply.
  • At launch, 19 platforms support linked billing, including Asana, Linear, Ramp, Railway, Warp and ClickHouse. Partner companies praised the added security.

Why it matters: Teams can pay for Claude inside other tools without sharing API keys. This lowers the risk of key leaks.

EU AI Act Accessibility Obligations Start December 2027

The EU AI Act (a European law on artificial intelligence) is already in force. Its rules phase in until 2028, and they include accessibility for disabled users.

  • The Act sets safety and rights rules for AI used in the EU. It applies even to firms based outside the EU if their customers are in the EU.
  • Providers build and sell AI tools. Deployers use third-party AI tools in their own products or services.
  • Rules depend on four risk levels: unacceptable, high, limited and minimal.
  • Unacceptable-risk AI is banned. Examples include social scoring, emotion recognition at work, and AI that exploits age or disability. From December 2026, this also covers AI making non-consensual intimate images or child sexual abuse material (CSAM).
  • High-risk AI covers recruitment screening, university admissions, credit scoring and benefit eligibility. From December 2027, providers must meet accessibility standards (EN 301 549 and WCAG 2.2, the Web Content Accessibility Guidelines).
  • Limited-risk AI, such as chatbots and image generators, must tell users they are dealing with AI. These labels must also be accessible.
  • All organisations must train staff in AI literacy, meaning enough understanding to use AI safely.
  • The article is a guide from an accessibility consultancy, not the official legal text. It advises auditing AI use, testing with disabled users, and checking third-party tools.

Why it matters: Firms serving EU customers from Switzerland may need to comply, including for AI used in hiring or credit decisions.
