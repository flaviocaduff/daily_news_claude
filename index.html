US moves to cut China's remote access to AI chips

  • The US Commerce Department closes a loophole that let China, Russia and Iran rent remote access to restricted AI chips in Indonesia, Malaysia, Singapore, Thailand and Brazil.
  • Companies headquartered in those countries deemed high diversion risk need export licences, strict know-your-customer controls, and monthly reports on chip transactions and final destinations.
  • Advanced chips made for Chinese firms are presumed restricted, with licences required before shipment. The rule takes effect 90 days after Federal Register publication.
  • Stated rationale: preventing rival military, intelligence, cyber and weapons-related AI uses. Handelsblatt says the rules could slow Southeast Asia's data-centre boom and strain ties with allies.
  • The curbs were announced just before Trump's Asia trip and the ASEAN summit in Manila, where protesters also opposed a US-backed AI industrial park.
  • SCMP's preview says analysts see the Nvidia turmoil and the chip curbs as exposing a split between Washington and Silicon Valley over China policy.

  • Empa researchers in Thun built OptiMat Chat, letting scientists run computational materials tools through a plain-language text chat.

TLDR InfoSec

httpx Ruby Gem RCE via Oj Object-Mode JSON Deserialization

  • httpx 1.9.0 with the oj gem loaded and multi_json absent parses response bodies in Oj's default :object mode, allowing arbitrary Ruby object instantiation.
  • In Rails apps (ActiveSupport loaded), a gadget chain turns this into remote code execution as the app user when an attacker controls a fetched URL.
  • No user interaction needed. The payload can be staged through an ordinary multipart POST, which Rack stores as a tempfile reachable via /dev/fd/N.
  • Not affected if multi_json is installed, Oj.default_options is set to a safe mode, or an explicit safe mode is passed at the call site.
  • Fixed in httpx 1.9.1 (strict mode default, commit eeb785d). Workarounds: response.json(mode: :strict) or a safe process-wide Oj default.

TLDR DevOps

Apache Fixes Critical mod_http2 Flaw CVE-2026-119618 in 2.4.71

  • Apache released HTTP Server 2.4.71 on November 11 to fix CVE-2026-119618, a heap corruption flaw in mod_http2 that Apache says can lead to RCE.
  • Affects 2.4.55 through 2.4.70. Triggerable unauthenticated over HTTP/2, so only servers with HTTP/2 enabled are exposed.
  • Severity scores differ: Red Hat and Amazon rate it 9.8 (CVSS 3.1), CISA 8.1, and the CVE record carries no score. Red Hat rates RHEL 9 and 10 Important.
  • Reported independently by Anthropic's OSS Scanner (October 26) and Google Cloud Vulnerability Research (November 3). Public PoC shows heap corruption, not code execution.
  • No confirmed in-the-wild exploitation and no KEV listing. As of November 13, Debian, Ubuntu, Alpine, Fedora and Amazon Linux had fixes; SUSE and some RHEL rebuilds did not.
