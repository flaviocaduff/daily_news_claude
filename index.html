A hacking campaign linked to North Korea has infected over 7,600 GitHub code repositories with malware. The campaign is called PolinRider.Eine mit Nordkorea verbundene Hackerkampagne hat über 7'600 GitHub-Code-Repositories mit Malware infiziert. Die Kampagne heisst PolinRider.

  • Apiiro researchers count 7,609 affected repositories. About 86% belong to older personal accounts with real activity. Only 16 owners look like throwaway accounts.
  • The activity may date back to February 2025.
  • The malware is a small Python loader. It hides in a utils package or a conftest.py file. When Python imports it, the loader reads a hidden instruction stored in an Ethereum (blockchain) wallet and runs it with Node.js.
  • SafeDep found the loader in 375 public repositories from 260 accounts. It found no sign the loader spread through PyPI or npm, public code package sites.
  • Fake job offers are a key entry point. Decoy sites such as BlockNovas, AccuraSoftHire and HuntRole ask applicants to run malicious take-home test projects. PolinRider is linked to the wider Contagious Interview campaign, which uses this kind of tactic.

Der Beitrag konzentriert sich darauf, was kaputtging und wie er es behob.

  • Since October 31, a coordinator (a main AI session) has run on his Mac each day, from morning to evening.
  • The coordinator uses Claude Code, a coding tool, and a written manual. It splits tasks, hands them to worker sessions, and reports to him on his phone.
  • The work covers email, app updates, servers, and research. Payments are off limits: the agents stop at checkout.
  • The context window (the text an AI can hold at once) fills by mid-afternoon. Warnings at 70% and 85% trigger a handoff file and a fresh session. There have been 35 sessions so far.
  • A session started by a scheduled job could not turn on phone access without a click, so it stayed hidden from his phone.
  • On November 11, an old session still answering "good morning" cost him a day of desktop work.
  • A listener (a client that waits for new messages) exited every 30 minutes at first. On November 14, that caused 24 empty wake-ups.
  • On November 13, one worker used about 77% of roughly 1.3 billion context tokens (units of text an AI reads). Its wait tool returned at once, so it looped.
  • Seit dem 31. Oktober läuft auf seinem Mac jeden Tag von morgens bis abends ein Koordinator, also eine Haupt-KI-Sitzung.
  • Der Koordinator nutzt Claude Code, ein Programmierwerkzeug, und ein schriftliches Handbuch. Er teilt Aufgaben auf, übergibt sie an Worker-Sitzungen und berichtet ihm auf dem Handy.
  • Die Arbeit umfasst E-Mails, App-Updates, Server und Recherche. Zahlungen sind tabu: Die Agenten halten an der Kasse an.
  • Das Kontextfenster (der Text, den eine KI gleichzeitig halten kann) füllt sich bis am Nachmittag. Warnungen bei 70 % und 85 % lösen eine Übergabedatei und eine frische Sitzung aus. Bisher gab es 35 Sitzungen.
  • Eine von einem geplanten Job gestartete Sitzung konnte den Telefonzugriff nicht ohne Klick aktivieren und blieb deshalb auf seinem Handy unsichtbar.
  • Am 11. November kostete ihn eine alte Sitzung, die immer noch auf «good morning» antwortete, einen Tag Arbeit am Desktop.
  • Ein Listener (ein Client, der auf neue Nachrichten wartet) beendete sich anfangs alle 30 Minuten. Am 14. November führte das zu 24 leeren Weckvorgängen.
  • Am 13. November verbrauchte ein Worker rund 77 % von etwa 1,3 Milliarden Kontext-Tokens (Texteinheiten, die eine KI liest). Sein Wartewerkzeug kehrte sofort zurück, weshalb er in einer Schleife lief.
