OpenAI launches GPT-6.2 Astra and Sol on ChatGPT and APIs

OpenAI released two new AI models, GPT-6.2 Astra and GPT-6.2 Sol. Astra is for the hardest work, and Sol is for everyday tasks.

  • Both models roll out now to paid ChatGPT users on Plus, Pro, Enterprise and Edu plans. Developers can use them through the API (the interface software uses to call the model). A shorter second source confirms the launch.
  • On Agents' Last Exam, a test of multistep professional work, Astra scores 5.2 points above GPT-6 Astra. It costs under a third as much. It also scores 5.5 points above Anthropic's Claude Fable 5.2, at 5% of its cost.
  • OpenAI calls Astra the best model for scientists. It beats GPT-6 Astra by 9 percentage points on Terminal-Bench-Science 0.1, and sets new highs on the Vals Science Index.
  • On the AA-3D test, Astra scores 1,318 Elo (a rating from head-to-head comparisons). That beats Fable 5.2 at 1,271 and Sol at 1,259. It more than doubles Fable 5.2's pass rate on Harvey LAB-AA legal tasks.
  • Astra writes cleaner code and matches document templates, even from a screenshot. Early testers Harvey, Legora and ClickUp report fewer tokens (chunks of text that set cost) and fewer review rounds. Accounting firm Basis says its work takes 50% less time.
  • Sol comes within 0.5 points of Astra on Cognition's FrontierCode 2.0 test, at about a fifth of the cost. It also outscores GPT-6 Astra on LifeVal, at about a seventh of the cost.
  • API prices per million tokens: Astra costs $8 for input and $40 for output, 20% less than GPT-6 Astra. Sol keeps its $2 and $10 prices. Ultrafast is available to Pro 500 users and in the API, and reaches Pro 200 for the first time with Sol.
  • Both models meet OpenAI's 'Critical' cybersecurity and 'High' biological and chemical risk levels in its Preparedness Framework (its internal risk rules). Astra is the first externally released OpenAI model at the High level for AI self-improvement. Tighter cyber safeguards may also block some legitimate security research.

Why it matters: Cheaper, stronger models could shift which AI tools developers and professionals choose.

Java4Shell: Critical OpenJDK Base64 Decoder RCE Flaw

Researchers at Calif disclosed Java4Shell, a critical flaw in Java's Base64 decoder. It can let attackers run code on popular business servers without logging in.

  • The flaw has the ID CVE-2026-114938. It scores 9.2 out of 10 on CVSS 4.0, a standard severity scale.
  • It sits in OpenJDK, the most common Java runtime (the software that runs Java programs). Base64 is a common way to encode binary data as text.
  • The bug is in optimized assembly code. It lets malformed input overwrite nearby memory.
  • Depending on use, it can leak memory like Heartbleed or allow remote code execution (RCE, running attacker commands).
  • Trigger input is 64 'A' characters followed by '='. OpenJDK 17 needs 128 'A' characters followed by '='.
  • Calif showed RCE without login in Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate. Kafka, Solr, Elasticsearch, Gerrit and Spinnaker need a login.
  • Calif also showed RCE in sample apps built on Apache Struts and Spring Boot. A client-side exploit by samczsun affects Java programs that open TLS connections to malicious servers.
  • Calif used AI to find and exploit the bug: about one hour to find it and two more to build the first exploit. The token cost was under $200.

Why it matters: Java runs in banking, aviation and government systems. Admins of affected servers should check for patches and mitigations.

Uber's Lifecycle Framework Governs Autonomous AI Agents

Uber Engineering described a security framework for AI agents (software that takes actions on its own). It checks whether each action fits the user's request, the agent's purpose and its permissions.

  • Normal login and access controls only check whether an agent may use a resource. They cannot judge whether a specific action is appropriate.
  • The framework targets risks like prompt injection (hidden instructions that trick an AI), tool and memory poisoning, goal hijacking, behavioral drift and hallucination-driven actions (acting on invented facts).
  • It has three layers: before deployment, at runtime, and after deployment. Agents must be registered in the Uber AI Registry with their owner, purpose, permitted actions and risk level.
  • Argus, an automated tool, scans each agent's source code, prompts, settings and tool-calling paths for weaknesses. The same checks apply to MCP servers (connectors that link AI to outside tools).
  • At runtime, AI Guards check each proposed action against policy before it runs. After deployment, full logs let teams replay past interactions when policies change.
  • Uber says its strongest control was restricting agents to explicit constraints, which is least privilege (granting only the access needed). Generic thresholds failed because each agent has different risks.
  • Uber reports challenges: avoiding false positives, keeping delays low, and reducing setup friction for developers. The framework is still evolving.
  • Commentary on LinkedIn from a UN IT officer and an AI architect notes that per-agent rules cost effort that grows with each workflow. One asks how this applies to vendor agents where firms cannot add their own checks.

Why it matters: It shows how one large company tries to control AI agents that act on live systems.

Stripe index: non-AI B2B software revenue up 30%+ YoY

Stripe's economics team, led by economist Ernie Tedeschi, launched a weekly index of revenue at non-AI software firms. It shows sales kept growing through early 2026's software stock sell-off, but the author warns the sell-off could still hit revenue later.

  • The index tracks weekly revenue at about 72,000 non-AI software firms that take payments through Stripe. Year-over-year growth (compared with a year earlier) is above 30%.
  • That matches the highs of summer 2023. By early February 2026, nearly $1 trillion of software stock value had been wiped out. Counting later weeks, the loss may have reached about $2 trillion.
  • Stripe says B2B (business-to-business) software stocks have since recovered to roughly their pre-sell-off levels. The index sits about 4% above its pre-sell-off trend.
  • It grew 14% from early May to late December 2025, then about 21% more since January, over a comparable stretch. Firms under one year old grow fastest, though growth has cooled lately.
  • Firms a year or older slowed from late 2025. The sell-off appears to have stopped that slowdown, and their growth is back near its mid-2025 pace. The typical (median) company only recovered to trend.
  • Caveat: the sample is mostly self-serve firms that take card payments online. Most of the lost value belonged to large public firms with sales teams and annual contracts, and little of their revenue runs through Stripe.
  • The index counts price rises as growth and ignores costs and profit margins. Firms that shut down drop out, rather than counting as a 100% fall. TLDR's commentary says these caveats make 'RenaiSaaS' (a software revival label) too strong.

Anthropic adds linked billing for Claude Platform tools (beta)

Anthropic, maker of the Claude AI models, launched 'linked billing' in beta (an early test version). Third-party apps can now let their users pay for Claude usage without sharing a password-style key.

  • Third-party tools, such as coding agents and workflow automation apps, can let users pay for their Claude API usage. The API is the way software calls Claude.
  • Today, users often share an API key, a password-style access code, with the tool. Anyone holding that key can make billed requests.
  • With linked billing, users link their Claude Platform organization instead. No key changes hands, and platforms store no customer keys.
  • Users approve each platform and set monthly spend limits, per platform or as a default. They can see spend in Console (Anthropic's developer dashboard) and unlink at any time.
  • Platforms see each customer's request count, token usage (units of text the model processes) and models used. They can choose per request whether they or the customer pays.
  • Anthropic hosts the approval and billing, so platforms skip building metering and invoicing. Customers can draw on existing Anthropic prepaid commitments or pay as they go.
  • Requests run in the platform's organization, so the customer's own settings do not apply. These include IP allowlists, encryption keys and data retention.
  • 19 platforms support it today: Asana, ClickHouse, Factory, Gumloop, Harness, Higgsfield AI, Kilo Code, Linear, Major, Mintlify, Omni, OpenArt, Niteshift, Railway, Ramp, Runlayer, Tessera, Tines and Warp. Platforms add support by creating an app in Console.

Why it matters: Users can pay for third-party AI tools without giving those tools a password-style key.
